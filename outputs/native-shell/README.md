# Native desktop client

Rust/GTK 4 client over the authenticated, durable presentation contract in `../agent-shell`. Reusable controls come from a versioned public 716 UI release. Documents contain inert data; the renderer keeps stable native widgets, preserves selected text and local drafts, reads live core job bindings, and dispatches opaque host action references. IPC runs separately from GTK input/rendering.

New document and Import are available on an empty desktop. They create a “Personal” activity internally after a valid request; later documents reuse the selected activity. Cancelling file selection or rejecting an unreadable file does not create an activity.

The shell includes activity selection/creation, explicit agent requests, actual core/broker job monitoring, output inspection and direct cancellation. Local microphone capture requires transcript review; the submitted request retains its original activity, selected output and stop generation. Appearance, text scaling and reduced-motion controls are local and persistent. `agent-os-setup` provides deliberate network/audio/provider setup in an ordinary Linux terminal.

Build on ARM64 Linux with Rust 1.85.1, GTK ≥4.12 and the locked dependencies:

```sh
cargo build --locked
cargo build --release --locked --manifest-path ../agent-shell/Cargo.toml
dbus-run-session -- python3 tests/native_desktop.py
```

`--socket PATH` selects an isolated core; `--activity ID` sets the initial activity. The normal core socket is `/run/agent-os/runtime.sock`. The explicit verification mode requires a fixture and a private graphical display; it never submits real model requests. Tests always reap their display, core, compositor and app processes.

`tests/native_desktop.py --compositor` also requires a built `../native-compositor` and tests mixed native/conventional Wayland clients, floating/maximized/tiled placement, exact revisions, undo and no focus stealing. Add `--shared` to exercise core-owned workspaces, authenticated renderer identities, durable focus, journal undo and activity visibility. CI evidence is ARM64 Linux nested graphical verification, not a UTM release qualification.

The native monitor includes typed workspace arrangement controls, proposal review/rejection/approval, conventional terminal attachment and a local rescue terminal. Unsaved local text has a private atomic recovery cache in XDG_STATE_HOME. Output inspection uses bounded pages and preserves a selection while a new page is pending. Installed broker approval/rejection, stored-input inspection, direct stop and PTY attachment pass the automated UTM suite.

Output removal/recovery, virtualized collections, shared terminal projection, paged document transport, typed callback fields, lease-owned pointer grabs and measured layout pressure are implemented and covered by automated Linux checks. The UTM suite qualifies native/session lifecycle and the opt-in direct DRM backend with kernel input, VT switching and clipboard/drop journeys. Still required: physical multi-output/hotplug and input delivery, full assistive journeys, live agent-generated composition quality and full reference parity. See `../implementation-status.md` for the accepted scope and evidence boundaries.

Graphical runtime packaging is enabled by the release contract. `../agent-shell/install.sh` builds both graphical executables and collects the locked dependency notices before staging; activation exposes `agent-os-session` and an agentOS Wayland session entry. Compatible rollback includes these bindings. Start from an ordinary local login with a private XDG_RUNTIME_DIR. The session owns a Weston kiosk display host and the nested agentOS compositor; Weston uses its DRM backend for a physical/VM display. Headless and nested Wayland session modes are explicit test options. This integration does not yet replace the nested compositor with a direct DRM backend or qualify multiple outputs.

`tests/native_session.py` exercises the complete normal session against an isolated core, including authenticated surface mapping and cleanup of the host, compositor and renderer. `../agent-shell/tests/graphical_release.py` stages real ARM64 ELF programs and verifies complete hashed dependency notices without activating the runner's system. These checks complement, and do not replace, UTM cold-boot qualification.

The compositor reserves Ctrl+Alt+Tab (Shift reverses), Ctrl+Alt+F10/F9/F8 (maximize/restore/float), Ctrl+Alt+arrows (move; Shift resizes), Ctrl+Alt+Delete (close) and Ctrl+Alt+Z (undo its last arrangement). Other keyboard input passes through. Arrangement controls in Agent Monitor remain available through native keyboard navigation. Physical shortcut delivery and assistive journeys still require UTM qualification. Pointer move/resize requests use process-owned workspace leases, local previews and an exact final revision; interruption releases the lease. Manual required geometry cannot be silently reshaped by agent updates.

Typed action parameters can use literals or the current local value of a declared TextField. Button activation and text-field submit include the presented surface revision. Host schemas reject changed targets, unsupported keys and out-of-range values. A lost response is reconciled through its receipt instead of replaying an effect.

Oversized clients retain their logical size. Ctrl+Alt+PageUp/PageDown pans vertically, with Shift for horizontal panning. Offsets are local viewport state and do not rewrite the WorkspaceDocument; hidden views retain their geometry, and offsets survive activity switches while the application remains open. The same-login `viewport.pan` control accepts one bounded step per axis for native controls and integration checks.

Native operation review includes an explicit **Inspect stored input** control. It rechecks the frozen proposal, obtains the bytes through the administrator-only broker API, and displays literal text in a read-only selectable widget. It uses noninteractive sudo, reports unavailable administrator access and runs off the GTK loop. Stored input is never added to ordinary job snapshots or draft caches. The broker verifies input length and fingerprint before preview or launch. Full approval/rejection and input inspection still await guest qualification.

Output observations now expose logical geometry, scale, transform, connection state and process-backed availability through paged `outputs.list`. Resizing or disconnecting an output retains saved placements; unrelated text edits and removal of retained views remain possible. New placements must fit a connected output. Views assigned to an unavailable output are temporarily reachable in a preserved-layout overview on the current nested output, and the arrangement chooser lists available destinations. This recovery policy has headless integration checks; physical multi-monitor routing and direct DRM ownership remain outstanding.

The native host ensures stable, user-owned inspect/read-output/stop callback references for selected activity jobs. Shared terminal views do the same when opened. Agent presentation snapshots expose the first discovery page; `presentation_actions` reads subsequent pages. Models can reference discovered callbacks in inert documents but cannot register or invoke them. Defaults survive restart and preserve revocation; registration has no execution effect.

`window:<host-surface-id>` sources expose read-only `/title`, `/app_id` and `/availability` fields. The compositor owns their activity association and observations; title/identity changes increment source revisions, and a dead compositor makes its values explicitly unavailable. `source.list` pages through conventional windows and core/broker jobs using registered paths. Models cannot publish window observations.

The work monitor follows inspected live output in bounded pages. “Follow live output” pauses/resumes delivery; selecting text freezes the displayed page and preserves its grounding offsets. Previous, Next and Refresh explicitly pause following. Connection failures retain the last page and retry without replacing selected text.

Work history uses GTK ListView virtualization with stable model identities. Recycled rows clear their previous command targets, and updates refresh mounted rows without replacing their controls. A 4,000-record graphical verification checks bounded widget construction, stable updates and cleared targets; core history arrives through byte-bounded, revision-consistent pages.

`Table@1` uses the pinned 716 UI alpha.3 virtualized native table. Required properties are `label`, `columns` (1–32 strings) and `rows` (up to 10,000 objects with unique `id` and matching string `cells`). Surface byte limits still apply. Table contents are read-only data, with native selection and resizable headers; no row grants action authority. Focus leases prevent external document replacement during active input. Terminal views display the same header and row data as sanitized text. Paged collection source adapters and further collection components remain work in progress.

An experimental direct display backend is compiled by the compositor’s default `direct-display` feature. Explicitly set `AGENT_OS_COMPOSITOR_BACKEND=drm` when invoking the compositor from a local seat; `AGENT_OS_DRM_DEVICE` optionally selects a DRM card belonging to that seat. It uses libseat for device ownership, libinput for physical keyboard/pointer delivery, GBM/GLES scanout and software cursor rendering. Ctrl+Alt+F1–F6 switches virtual terminals; existing F8/F9/F10 arrangement controls remain available. The nested backend remains the session default. The dedicated ARM64 UTM guest qualifies completed KMS frames, output discovery, VT switch/resume, kernel/libinput keyboard and absolute pointer, clipboard, undo/redo, exact draft/Save, workspace move/resize/maximize/restore/undo and owned-session cleanup. Physical host delivery, GPU behavior, hotplug and physical multi-output/scaling remain unqualified.

Direct sessions can be selected with `agent-os-session --backend direct`; they own the agentOS compositor and renderer without starting Weston. The ordinary `drm` session option still uses the established Weston host. Direct output preferences are read at compositor startup from `$XDG_CONFIG_HOME/agentos/outputs.json` (or `~/.config/agentos/outputs.json`): `{"outputs":{"DisplayPort-1":{"scale":1.5,"x":0,"y":0,"mode":{"width":2560,"height":1440,"refresh_millihz":60000}}}}`. Use the connector name reported by the compositor; omit `mode` for its preferred mode, omit both coordinates for side-by-side placement, and omit `scale` for 1. Invalid preferences fail before seat/device configuration. Scaling and positions use logical coordinates; saved core workspaces remain associated with stable `drm-<connector>` output IDs. Physical modes, connector availability, VT recovery and multi-output input still require guest qualification.

Each graphical login now isolates its display sockets in a private session runtime directory. The launcher adopts orphaned descendants for bounded teardown, and the renderer receives SIGTERM if its compositor dies before normal cleanup. CI includes abrupt compositor loss in addition to ordinary logout and display-host loss; session directories and owned processes must disappear after all three paths.

716 UI alpha.8 adds native `List@1` and `KeyValue@1` rendering. Both require a meaningful `label` and keyed `rows`; List rows have exactly one string cell, KeyValue rows have exactly two. The same 10,000-row/key/cell bounds apply as Table. Native rows are virtualized and retain selection by key; focus leases preserve active interaction. Shared terminal views project lists and key/value pairs as sanitized read-only text. These components do not carry action authority.

Shared documents use `DocumentEditor@1` with Unicode literal find/replace and grouped undo. New document opens an untitled shared document. Save/Discard uses human-owned drafts and checks the displayed revision; concurrent changes retain the draft for review. Document content is bounded to 64 KiB. Import text file uses a local file chooser and strict UTF-8 regular files up to 64 KiB. Export saved document uses a local chooser, checks the displayed revision and unresolved drafts, and creates a new private file exclusively; existing files are preserved. These operations run as the human desktop user. Review replacement of existing file shows selectable current and replacement text, then requires deliberate replacement using the displayed document revision and reviewed file hash. The original is retained in private human recovery storage, with ownership/mode preserved. Privileged edits remain broker operations.

`tests/pty_broker.py` exercises the native Rust terminal transport against the real broker handler, tmux and OS PTYs: Unicode input, SIGWINCH, detach, screen restoration and display-reader cleanup. It supplies an isolated job record directly; systemd launch policy remains covered by separate guest tests. Attachment allows three seconds for the broker’s bounded screen-reader setup. An uncertain acknowledgement sends no input and directs the user to wait for the controller lease to expire rather than automatically attaching again.

Arrange workspace includes explicit application reconnection: select a disconnected conventional view and the live returning application as the second surface. The core checks exact window metadata and workspace revisions, atomically removes the transient placement, and retains the missing view’s identity, references and placement. Receipts are idempotent. Automatic compositor recovery is limited to one unambiguous authenticated client-process identity whose previous compositor is dead. No app is relaunched and app-owned document state is not reconstructed.

Opt-in diagnostics: set `AGENT_OS_METRICS_DIR` to an existing absolute directory. On clean process shutdown, native/compositor clients write mode-0600 `render-PID.json` files containing at most eight stages and the latest 256 durations per stage, cumulative counts/mean, recent p50/p95/max and discarded sample counts. Native update and revision-reconciliation attempts are separate; nested render/submit and direct render attempts have distinct stages. No document text, IDs, input, paths or credentials enter the report. These CPU/submit timings do not establish input-to-display latency or physical GPU presentation. Linux rendering journeys retain the reports as artifacts.

Revision conflicts keep the human draft. Review latest version shows the current saved value beside that draft; Save reviewed draft checks the exact displayed document revision, reviewed draft revision and text. A changed core or local draft requires another review. Merely opening or canceling the comparison never commits.

Linux native rendering checks run saved light/dark preferences at text scales 1 and 2, with reduced motion at scale 2, then repeat under two bounded CPU workers. Each profile has separate screenshots, logs and metrics. The same persisted preferences are applied at startup and by the verification host. CPU contention does not simulate actual inference, and these checks do not qualify physical input or display latency.

The full desktop session also has an independent AT-SPI journey that edits Unicode text, observes a retained core draft without committing, deliberately saves, and discards a later edit. This tests assistive API semantics; spoken screen-reader output and physical keyboard navigation remain qualification work. Draft action buttons wrap on narrow views. Captures include the native window background, and an 800×600 profile at text scale 2 rejects windows wider than the logical output.

An optional Wayland input method can be selected by the human session configuration with `AGENT_OS_INPUT_METHOD_ARGV`, a JSON array beginning with an absolute executable path. The compositor passes that helper a private inherited `WAYLAND_SOCKET`; only that connection can bind `zwp_input_method_manager_v2`. Ordinary clients receive text-input-v3 support but cannot register an input method, including by guessing the hidden global ID. No PID, title or app-id grants this capability. The helper runs in its own owned process group and is terminated/reaped when the compositor exits; helper failure ends the session with an error, preserving the independently supervised core. Without a configured helper, these globals are not advertised and existing GTK input handling remains available. The protocol test covers Unicode preedit/commit, focus loss and forced-bind denial; real engine, candidate popup and physical keyboard journeys still require qualification before recommending a particular helper configuration.

The October 10 transfer qualification uses kernel uinput, distinct GTK Wayland clients and the direct compositor: primary middle-paste after explicit focus navigation, Unicode COPY drops, native grouped undo, oversized rejection and drag-icon rendering/removal pass. These checks wait for focus acknowledgements; they do not establish rapid cross-window input latency or physical host delivery. The renderer pins public 716 UI `v0.1.0-alpha.25`, including variant-specific button hover, nearest insertion positions in blank editor space, measured default button dimensions and reference-aligned 150 ms background transitions. Full appearance/motion parity remains unqualified.

The alpha.22 native Input correction includes dark input/30, explicit disabled opacity, pinned muted placeholders and delegated Entry focus through `:focus-within`. Public regressions check painted backgrounds and every edge of the actual native focus ring; full reference parity remains unqualified.

The Debian runtime dependency profile includes Firefox ESR and GIO desktop handlers for HTTP/HTTPS links. `tests/browser_links.py` checks those system handlers, activates a real native Link through AT-SPI, and verifies Firefox retrieves a local page and joins the shared conventional workspace with durable focus/maximize and disconnect. The test uses a private handler only to launch an isolated disposable browser profile and track its process group; it does not replace the user's default handler. `--installed` exercises the immutable release executables. Cleanup removes the browser group, profile, native clients and private displays. Remote website compatibility, physical browser input, acceleration and mail client configuration remain separate qualification.

Alpha.23 adds measured default horizontal Tabs strip/trigger paint and typography checks with independent AT-SPI selection. Alpha.24 corrects bounded Chart scaling for signed fractions, tiny and subnormal values; both themes have actual bar-paint regressions. These scoped checks do not establish full shadcn parity.

Native PTY controls now re-enable Attach after deliberate Detach without needing an unrelated source refresh. An unavailable source stays disabled across timer ticks, and recovery never attaches automatically. The real broker/tmux fixture exercises actual GTK controls, repeated attachment and source outage, verifies detached broker tokens/readers, and checks that closed terminal widgets release their Rust owner. The input signal uses a weak owner to avoid retaining the VTE widget after closure. The separate installed direct-display journey now qualifies kernel keyboard/pointer delivery and Unicode Wayland clipboard paste through VTE into the real broker PTY, plus explicit detach/reattach. Physical delivery and VTE IME remain unqualified.

`tests/first_document.py` verifies an empty core through native controls and the shared compositor, including one implicit activity reused by two documents and native chooser acceptance/cancellation. `--queued` additionally exercises two requests queued before the UI snapshot refreshes; they must reuse one confirmed activity. `--import` additionally requires an installed runtime helper and verifies rejected-file handling and an initial Unicode import through the actual backend.

Native terminal shortcuts use Ctrl+Shift+C for copy and Ctrl+Shift+V for paste. Paste requires an explicitly attached session; ordinary Ctrl+C remains program input. The key controller holds a weak terminal owner, and the existing transport rejects oversized writes as a whole.

Pointer grabs acquire their core lease once. If the scene revision lags only renderer element-focus bookkeeping, the compositor reads the current workspace under that lease and freezes the confirmed revision. Geometry, constraints, activity, focused surface, unknown policy fields or a newer-than-leased revision still reject the grab and release its lease. No interaction-begin request is replayed.

Native terminals expose explicitly named Copy/Paste menu items through right-click, Shift+F10 or the Menu key. Copy requires a selection; Paste requires explicit attachment and rechecks that state when invoked. The menu shares its guarded actions with Ctrl+Shift+C/V and returns local focus when dismissed. Compositor popup cleanup restores the authoritative workspace focus without waiting for another key, and preserves the first absolute pointer motion after an ended popup grab. No click or execution action is replayed.

The installed terminal journey selects a real Unicode output line with kernel pointer input and reads its exact text (including its selected newline) in a separate Wayland client. It verifies keyboard/menu Copy, accessible menu Paste, menu dismissal and seat-focus recovery, disabled detached Paste, reattachment and ordinary Ctrl+C program interruption. Synthetic kernel input qualifies this VM stack; physical input and VTE IME remain unqualified.
